# Database Triggers Documentation

This document explains the MySQL database triggers implemented in the **Hospital Management System (HMS)**, specifically focusing on the validation triggers active on the `patient` table during profile updates (`public/patient/edit.php`).

---

## 1. Overview of Patient Update Trigger

When a patient updates their personal profile information via the **Edit Profile** interface (`public/patient/edit.php`), MySQL automatically executes the `BEFORE UPDATE` trigger on the `patient` table.

The trigger acts as a database-level integrity firewall. If any submitted data violates the business constraints, MySQL interrupts the `UPDATE` query using `SIGNAL SQLSTATE '45000'` with a custom error message.

---

## 2. The 3 Trigger Validations Explained

### Validation 1: Prevent Future Date of Birth
- **Rule**: A patient cannot have a date of birth set in the future.
- **Trigger Logic**: Compares `NEW.date_of_birth` against MySQL's `CURRENT_DATE()`.
- **Error Raised**: `Trigger Error: Date of birth cannot be in the future.`

### Validation 2: Medical Blood Group Whitelist
- **Rule**: If provided, the blood group must be one of the standard medical blood groups (`A+`, `A-`, `B+`, `B-`, `AB+`, `AB-`, `O+`, `O-`).
- **Trigger Logic**: Checks `NEW.blood_group NOT IN ('A+', 'A-', 'B+', 'B-', 'AB+', 'AB-', 'O+', 'O-')`.
- **Error Raised**: `Trigger Error: Invalid blood group. Must be A+, A-, B+, B-, AB+, AB-, O+, or O-.`

### Validation 3: Emergency Contact Number Length
- **Rule**: If provided, the emergency contact phone number must be at least 11 digits long.
- **Trigger Logic**: Checks `CHAR_LENGTH(NEW.emergency_contact) < 11`.
- **Error Raised**: `Trigger Error: Emergency contact must be at least 11 digits.`

## 3. SQL Trigger Code

### Combined Trigger Implementation (`chk_patient_update_validation`)

```sql
-- Remove any legacy trigger if exists
DROP TRIGGER IF EXISTS `chk_patient_dob_update`;
DROP TRIGGER IF EXISTS `chk_patient_update_validation`;

DELIMITER $$

CREATE TRIGGER `chk_patient_update_validation` 
BEFORE UPDATE ON `patient` 
FOR EACH ROW 
BEGIN
    -- 1. Date of Birth Validation
    IF NEW.date_of_birth IS NOT NULL AND NEW.date_of_birth > CURRENT_DATE() THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'Trigger Error: Date of birth cannot be in the future.';
    END IF;

    -- 2. Blood Group Validation
    IF NEW.blood_group IS NOT NULL AND NEW.blood_group != '' 
       AND NEW.blood_group NOT IN ('A+', 'A-', 'B+', 'B-', 'AB+', 'AB-', 'O+', 'O-') THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'Trigger Error: Invalid blood group. Must be A+, A-, B+, B-, AB+, AB-', 'O+', or 'O-.';
    END IF;

    -- 3. Emergency Contact Length Validation
    IF NEW.emergency_contact IS NOT NULL AND NEW.emergency_contact != '' 
       AND CHAR_LENGTH(NEW.emergency_contact) < 11 THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'Trigger Error: Emergency contact must be at least 11 digits.';
    END IF;
END$$

DELIMITER ;
```

## 4. Other Active Triggers in HMS Database

### A. Insert Validation on Patient (`chk_patient_dob_insert`)
Fires before inserting a new patient to ensure the date of birth is not in the future:
```sql
DELIMITER $$
CREATE TRIGGER `chk_patient_dob_insert` BEFORE INSERT ON `patient` FOR EACH ROW BEGIN
    IF NEW.date_of_birth > CURRENT_DATE() THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'Date of birth cannot be in the future.';
    END IF;
END$$
DELIMITER ;
```

### B. Automatic Total Calculation on Bill (`calculate_total_amount_insert` / `calculate_total_amount_update`)
Automatically calculates `total_amount = doctor_fee + medicine_cost` whenever a billing row is inserted or updated:
```sql
DELIMITER $$
CREATE TRIGGER `calculate_total_amount_insert` BEFORE INSERT ON `bill` FOR EACH ROW BEGIN
    SET NEW.total_amount = NEW.doctor_fee + NEW.medicine_cost;
END$$

CREATE TRIGGER `calculate_total_amount_update` BEFORE UPDATE ON `bill` FOR EACH ROW BEGIN
    SET NEW.total_amount = NEW.doctor_fee + NEW.medicine_cost;
END$$
DELIMITER ;
```

## 5. Web Application Integration (`public/patient/edit.php`)

In PHP, database trigger rejections throw a `PDOException`. The application captures the exact trigger error message (`$e->errorInfo[2]`) and sends it back in the JSON response:

```php
try {
    $stmt = $pdo->prepare("
        UPDATE patient
        SET gender = ?, date_of_birth = ?, blood_group = ?, address = ?, emergency_contact = ?
        WHERE user_id = ?
    ");
    $stmt->execute([$gender, $dateOfBirth, $bloodGroup, $address, $emergencyContact, $userId]);

    echo json_encode(['success' => true, 'message' => 'Profile updated successfully!']);
} catch (PDOException $e) {
    // Extracts the custom message generated by the SQL Trigger
    $triggerMsg = $e->errorInfo[2] ?? 'Update failed. Please check your inputs.';
    echo json_encode(['success' => false, 'message' => $triggerMsg]);
}
```
